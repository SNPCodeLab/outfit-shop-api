OutfitShop Ecommerce Clothing API

The next-generation OutfitShop RESTful API for modern omnichannel fashion apparel, retail POS checkout, cart & wishlist synchronization, multi-store inventory matrices, and financial ledgers.

● Live REST / JSON Laravel 11 Sanctum Auth 4-Tier RBAC Cart & Wishlist

Who Is This For?

🌐

Public / End Users

Browse product data with no account needed.

  • View all products & variants
  • Browse categories & colors
  • Search by barcode / SKU
  • Check low-stock items
🔑

Cashier Staff

POS operators who handle sales daily.

  • Everything public users can do
  • Process POS checkout
  • Register & update customers
  • View sales history
🔒

Frontend Developers / Manager

Build the management dashboard UI.

  • Create, update, delete products
  • Manage categories, sizes, colors
  • Handle suppliers & purchases
  • View dashboard stats & audit logs
👑

System Administrator

Full control of the entire system.

  • Everything manager can do
  • Create & manage employees
  • Create new user accounts
  • Assign roles & permissions

How to Login

Send a POST request to /api/v1/auth/login with your username and password. You get back an access_token and a permissions[] list.

1

Send Login Request

Request 
POST  https://api.kesararamwithdigital.tech/api/v1/auth/login
Content-Type: application/json

{
  "username": "manager",
  "password": "your_password"
}
2

Receive Token + Permissions

Response · 200 OK 
{
  "success":      true,
  "message":      "Login successful",
  "data": {
    "access_token": "1|abc123xyz...",
    "token_type":   "Bearer",
    "account_type": "employee",
    "user": {
      "id":       2,
      "name":     "Store Manager",
      "username": "manager",
      "role":     "MANAGER",
      "permissions": [
        "catalog.read", "catalog.write",
        "customers.read", "customers.write",
        "sales.read", "sales.checkout",
        "suppliers.read", "purchases.read",
        "stock.adjust", "dashboard.view"
      ]
    }
  }
}
💡 Use permissions[], not role strings Check permissions.includes("catalog.write") on the frontend instead of checking the role name. This means you never need to update your UI code when roles change.
3

Store the token

JavaScript (fetch)
// After a successful login:
const { data } = await response.json();

localStorage.setItem('token',       data.access_token);
localStorage.setItem('permissions', JSON.stringify(data.user.permissions));
localStorage.setItem('role',        data.user.role);

Using the Token

Add the token to the Authorization header on every protected request.

JavaScript — All Protected Requests
const token = localStorage.getItem('token');

const response = await fetch('https://api.kesararamwithdigital.tech/api/v1/products', {
  method: 'GET',
  headers: {
    'Authorization': `Bearer ${token}`,
    'Content-Type':  'application/json',
    'Accept':         'application/json',
  }
});

const json = await response.json();
// json.data → your data
Frontend — Conditional UI with permissions
const permissions = JSON.parse(localStorage.getItem('permissions') || '[]');
const can = (perm) => permissions.includes(perm);

// Show "Edit" button only if user has write access:
if (can('catalog.write')) {
  document.getElementById('btn-edit-product').style.display = 'block';
}

// Show employee menu only for admin:
if (can('employees.write')) {
  document.getElementById('nav-employees').style.display = 'block';
}

GET /api/v1/categories No token
GET /api/v1/variants No token
GET /api/v1/clothing-sizes No token
GET /api/v1/colors No token
POST /api/v1/auth/login No token
🔑 AUTHENTICATED Any valid Bearer token (all roles)
GET /api/v1/auth/me Bearer
POST /api/v1/auth/logout Bearer
GET /api/v1/customers Bearer
POST /api/v1/customers Bearer
POST /api/v1/orders/checkout Bearer
GET /api/v1/orders Bearer
🔒 MANAGER Bearer token + role MANAGER or ADMIN
POST /api/v1/products Manager+
PUT /api/v1/products/{id} Manager+
DEL /api/v1/products/{id} Manager+
POST /api/v1/categories Manager+
GET /api/v1/suppliers Manager+
GET /api/v1/purchases Manager+
GET /api/v1/stock-movements Manager+
GET /api/v1/dashboard/stats Manager+
GET /api/v1/audit-logs Manager+

GET /api/v1/employees Admin only
POST /api/v1/employees Admin only
PUT /api/v1/employees/{id} Admin only
DEL /api/v1/employees/{id} Admin only
POST /api/v1/auth/register Admin only

Postman / Thunder Client / Insomnia

Import the ready-made collection files from the docs/ folder.

1

Download the files from GitHub

Files
docs/SS-MIS-API.postman_collection.json
docs/SS-MIS-Production.postman_environment.json
docs/SS-MIS-Local.postman_environment.json
2

Import into Postman

File → Import → drag all 3 files in at once.

3

Select environment

Top-right dropdown: choose SS-MIS — Production or SS-MIS — Local.

4

Login — token is saved automatically

Run Login (Admin) or Login (Manager). The test script auto-saves {{access_token}} to the environment. Every other request uses it automatically.

⚡ The collection includes RBAC test requests Look for the "⚡ RBAC — Permission Tests" folder. It has pre-built requests to verify that 401, 403, and 200 responses all work correctly.

cURL Examples

Public — no token

Shell
curl https://api.kesararamwithdigital.tech/api/v1/products

Login and capture token

Shell (bash)
TOKEN=$(curl -s -X POST https://api.kesararamwithdigital.tech/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"manager","password":"your_password"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['access_token'])")

echo "Token: $TOKEN"

Authenticated request

Shell
curl https://api.kesararamwithdigital.tech/api/v1/auth/me \
  -H "Authorization: Bearer $TOKEN"

Error Codes

HTTPerror_codeMeaning
401ERR_UNAUTHENTICATEDNo token or expired token
403ERR_FORBIDDENToken valid, but role too low. Check your_role and required_role in the response.
403ERR_ACCOUNT_INACTIVEEmployee account has been deactivated
404ERR_NOT_FOUNDResource with that ID does not exist
422ERR_VALIDATIONInput validation failed. Check errors object for field details.
500ERR_INTERNAL_SERVER_ERRORUnexpected server error

Example 403 Response

403 Forbidden
{
  "success":           false,
  "message":           "Forbidden. You do not have permission to perform this action.",
  "error_code":        "ERR_FORBIDDEN",
  "your_role":         "CASHIER",
  "required_role":     "MANAGER or ADMIN"
}

Standard Response Format

Every response follows the same envelope structure.

Success

200 / 201 OK
{
  "success": true,
  "message": "Products catalog retrieved",
  "data":    [ /* array or object */ ]
}

Validation Error

422 Unprocessable Entity
{
  "success":    false,
  "message":    "Validation Failed",
  "error_code": "ERR_VALIDATION",
  "errors": {
    "product_name": ["The product name field is required."],
    "category_id":  ["The selected category id is invalid."]
  }
}
